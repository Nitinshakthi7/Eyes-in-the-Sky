Part 2 – Srivalli: Data, EDA and the fixed split (Part A)

What my part is

My part is the data foundation of the project. Every model in the team (the scratch CNN, the transfer-learning models, the data-efficiency study and the explainability work) reads images through the code I wrote, so if my part is wrong, every result is wrong. I own three things: src/dataset.py (the code that loads the images, makes the split, normalises them, augments them and builds the data loaders), data/splits.csv (the saved list that says which image is in train, validation or test), and notebooks/01_eda.ipynb (the exploratory data analysis, with the leakage check at the top). The fixed split is the most important output: everybody uses the same 18,900 / 4,050 / 4,050 images, so every team member's score can be compared. The notebook shows what the data looks like (class counts, sample images, colours, histograms), and it checks that there is no leakage between the splits. I also explain why the augmentations (90-degree rotations and flips) are safe for satellite images, and why the test set must never be used while we make decisions.

Definitions

Term Simple meaning
EuroSAT A public dataset of satellite image patches, labelled with land-use classes. We use the RGB version.
Sentinel-2 A European Earth-observation satellite. EuroSAT images come from its multispectral sensor.
RGB Red, Green, Blue. The image has three colour channels, so we keep only the three visible bands.
Tile (patch) One small image cut from a larger satellite picture. In EuroSAT each tile is 64 x 64 pixels.
Class One land-use label, for example Forest or River. There are 10 classes.
Label The class number attached to an image. In our data the labels are 0 to 9.
Split One of the three parts of the data: train, validation (val) or test.
Train set The images the model learns from.
Validation set Images used during development to compare settings and to decide when to stop.
Test set Images kept back for the final score. They are not used to make decisions.
Stratified split A split that keeps each class at the same share in every part (for example 70% of each class goes to train).
Data leakage When information from the test (or validation) data reaches training, so the score looks better than it really is.
Leakage (exact copy) The same picture appearing in two splits, under the same or a different file name.
Leakage (neighbouring patches) Two tiles cut from the same large area land in different splits. They look alike, so this can still inflate the score. We could not remove this with a random split.
MD5 hash A short fingerprint (32 hex characters) computed from a file's bytes. Two files with the same MD5 have the same content.
Augmentation Making small changes to training images (rotate, flip) so the model sees more variety.
Label-safe augmentation An augmentation that does not change the true class of the image.
Rotation Turning the image around its centre. We use only 0, 90, 180 and 270 degrees, so no pixels are blurred.
Flip Mirroring the image left-right (horizontal) or top-bottom (vertical).
Normalisation Shifting and scaling pixel values with a fixed mean and standard deviation, so the numbers are in a similar range for the model.
ImageNet mean and std The fixed numbers (mean 0.485, 0.456, 0.406 and std 0.229, 0.224, 0.225 for R, G, B) that were measured on the ImageNet photo dataset. We use them for all models so the comparison is fair.
Tensor A PyTorch array of numbers. The model takes tensors, not PIL images.
PIL image An image object from the Pillow library. We read files as PIL images, then convert them.
Dataset (PyTorch) A class that knows how many items there are and returns item number i. Here it returns (image, label).
DataLoader A PyTorch helper that groups items from a Dataset into batches, can shuffle them and can load them in parallel.
Batch A group of images that the model processes together. We use 64 images per batch.
Shuffle Changing the order of the images each epoch, so the model does not see them in the same order every time.
Epoch One full pass through the training images.
Fraction The share of the training split we keep. For example 0.05 keeps 5% of train. Val and test never change.
Seed A number that starts a random generator. The same seed gives the same random choices, so a run can be repeated.
random_state The scikit-learn name for the seed.
Histogram A count of how many pixels have each value (0 to 255). It shows how bright or dark, and how spread out, the pixels are.
Per-channel Separately for each colour channel (red, green, blue).
Mean colour The average value of the red, green and blue pixels of one class.
Percentile The value below which a given share of pixels fall. The 5th percentile means 5% of pixels are darker than this value.
Clipping When bright pixels all go to the maximum value (255), so many pixels pile up at one value.
Class imbalance Classes that have different numbers of images. Here the ratio is at most 1.5 to 1.
Macro-F1 A score that averages the F1 score of each class equally, so small classes count as much as big ones. We report it with accuracy.
EDA Exploratory data analysis: looking at the data with counts and plots before training.
assert A Python statement that stops the program with an error if a condition is false.
pandas DataFrame A table in memory, with named columns. We use it for the list of images and their splits.
CSV A plain text table with commas between values.
scikit-learn train_test_split A function that cuts data into two parts, with optional stratification and a seed.
torchvision The PyTorch library for images. It gives us the EuroSAT dataset and the image transforms.
Lazy loading Reading an image from disk only when it is asked for, instead of holding all 27,000 in memory.
Ablation A test where one part is removed, to see how much it mattered.
Data-efficiency study Training with 5%, 10%, 25%, 50% and 100% of the train data, to see how the score changes with more data.
Reproducibility Being able to get the same result again from the same code, data and seed.

1.3 make_split(seed=42) (lines 41 to 67)

def make_split(seed=42):
    """Make the fixed 70/15/15 split and save it to data/splits.csv."""
    eurosat = load_eurosat()

    # One row per image. We save the path from the data folder with "/" so the
    # same file works on every laptop (the full path is different on each one).
    rows = []
    for path, label in eurosat.samples:
        relative_path = Path(path).relative_to(DATA_DIR).as_posix()
        rows.append((relative_path, label, eurosat.classes[label]))
    df = pd.DataFrame(rows, columns=["path", "label", "class_name"])

    # stratify= keeps the same share of each class in every part.
    # First cut: 70% train, 30% rest.
    train_idx, rest_idx = train_test_split(
        df.index, train_size=0.7, stratify=df["label"], random_state=seed)
    # Second cut: half of the rest is validation, half is test (15% + 15%).
    val_idx, test_idx = train_test_split(
        rest_idx, train_size=0.5, stratify=df.loc[rest_idx, "label"], random_state=seed)

    df.loc[train_idx, "split"] = "train"
    df.loc[val_idx, "split"] = "val"
    df.loc[test_idx, "split"] = "test"

    # lineterminator: same line endings on every laptop, so git sees no fake changes
    df.to_csv(SPLITS_CSV, index=False, lineterminator="\n")
    return df

1.4 check_split(df) (lines 70 to 89)

def check_split(df):
    """Prove there is no leakage. Stops with an error if something is wrong."""
    # 1. The split sizes are the expected ones.
    sizes = df["split"].value_counts().to_dict()
    assert sizes == SPLIT_SIZES, f"wrong split sizes: {sizes}"

    # 2. No file appears twice, so no file can be in two splits.
    assert df["path"].is_unique, "a file appears in more than one row"

    # 3. Every class has the same share in each split (at most 1 image off from exact rounding).
    counts = pd.crosstab(df["class_name"], df["split"])
    total_per_class = counts.sum(axis=1)
    for split, size in SPLIT_SIZES.items():
        expected = total_per_class * size / len(df)
        assert ((counts[split] - expected).abs() <= 1).all(), f"{split} is not stratified"

    print("Leakage check: OK")
    print(f"  split sizes: {sizes}")
    print("  no file appears in two splits; every class keeps its share in every split")
    return counts

1.5 augment() (lines 92 to 101)

def augment():
    """Random 90-degree rotation and flips. Only used on training images."""
    # A satellite looks straight down, so there is no "up": a rotated or flipped
    # field is still a field. The angles are exact, so no pixels get blurred.
    return transforms.Compose([
        transforms.RandomChoice([transforms.RandomRotation((angle, angle))
                                 for angle in (0, 90, 180, 270)]),
        transforms.RandomHorizontalFlip(p=0.5),
        transforms.RandomVerticalFlip(p=0.5),
    ])
Lines What it does (simple words) Concept Why we did it this way (and what else could be used)
96 Compose runs the steps in order: first rotation, then horizontal flip, then vertical flip. Transform pipeline Each step is applied to the output of the previous one.
97 to 98 RandomChoice picks one of four rotation objects: 0, 90, 180 or 270 degrees. (angle, angle) means the range from angle to the same angle, so the rotation is exact. Rotation, label-safe augmentation If we wrote RandomRotation(90), torchvision would pick any angle between -90 and +90 degrees, for example 37 degrees. That blurs the pixels and leaves dark empty corners. Exact right angles only move pixels.
99 RandomHorizontalFlip(p=0.5) flips left-right with a 50% chance. Flip With the rotations, this gives all 8 orientations of a square (4 rotations times 2 flips).
100 RandomVerticalFlip(p=0.5) flips top-bottom with a 50% chance. Flip Same as above.

The notebook (cell 20) checks that all 8 orientations really occur and that the pixel values do not change. Note that the flips are random, so one image can get any of the 8 orientations on different epochs.

1.6 make_transform(use_augment=False) (lines 104 to 108)

def make_transform(use_augment=False):
    """Turn a PIL image into a normalised tensor, with augmentation if asked."""
    steps = [augment()] if use_augment else []
    steps += [transforms.ToTensor(), transforms.Normalize(IMAGENET_MEAN, IMAGENET_STD)]
    return transforms.Compose(steps)
Lines What it does (simple words) Concept Why we did it this way (and what else could be used)
106 If augmentation is asked for, the list starts with augment(). Otherwise the list is empty. Conditional pipeline Validation and test use use_augment=False, so they are never augmented.
107 Adds ToTensor() and Normalize(...) to the list. Normalisation, tensor ToTensor() turns a PIL image of 0 to 255 integers into a float tensor of 0.0 to 1.0, in the order channel x height x width. Normalize then computes (x - mean) / std for each channel.
108 Returns the pipeline. Return value The Dataset calls this on every image it reads.

The augmentation runs before ToTensor() because it works on the PIL image. Rotating a tensor would also work, but the PIL version is the standard path.

1.7 EuroSATDataset (lines 111 to 125)

class EuroSATDataset(Dataset):
    """One part of the fixed split: gives back (image, label)."""

    def __init__(self, split, transform=None):
        df = pd.read_csv(SPLITS_CSV)
        self.df = df[df["split"] == split].reset_index(drop=True)
        self.transform = transform if transform is not None else make_transform()

    def __len__(self):
        return len(self.df)

    def __getitem__(self, i):
        row = self.df.iloc[i]
        image = Image.open(DATA_DIR / row["path"]).convert("RGB")
        return self.transform(image), int(row["label"])

1.8 get_loader(split, fraction, seed, augment, batch_size, num_workers) (lines 128 to 149)

def get_loader(split, fraction=1.0, seed=0, augment=False, batch_size=64, num_workers=0):
    """Make the DataLoader for "train", "val" or "test".

    fraction: share of the TRAIN split to use (stratified). val and test never shrink.
    seed:     picks the subset and the shuffle order, so a run can be repeated.
    augment:  rotations and flips, allowed only for the train split.
    """
    if split != "train" and (fraction != 1.0 or augment):
        raise ValueError("fraction and augment are only for the train split")

    data = EuroSATDataset(split, transform=make_transform(augment))

    if fraction < 1.0:
        # Keep the same class shares in the smaller training set.
        keep, _ = train_test_split(
            data.df.index, train_size=fraction, stratify=data.df["label"], random_state=seed)
        data.df = data.df.loc[sorted(keep)].reset_index(drop=True)

    # Only the training data is shuffled. The generator makes the order repeatable.
    generator = torch.Generator().manual_seed(seed)
    return DataLoader(data, batch_size=batch_size, shuffle=(split == "train"),
                      generator=generator, num_workers=num_workers)
Lines What it does (simple words) Concept Why we did it this way (and what else could be used)
135 to 136 Raises an error if someone asks for a fraction or augmentation on val or test. Guard against mistakes Val and test must be the same in every run. A mistake should stop the run, not quietly change the score.
138 Builds the Dataset for the split, with augmentation only if augment=True. Transform choice Train uses augment as asked. Val and test get augment=False because the guard above forces it.
140 to 144 If fraction < 1.0, keeps a stratified random subset of the training rows, with the same class shares, and replaces data.df with it. Stratified subset, data efficiency At 5% a plain random subset could leave a class with very few images. Stratifying keeps the shares. Different seeds give different subsets, which is what the data-efficiency study measures. sorted(keep) puts the rows back in file order, so the result does not depend on how scikit-learn shuffled them.
147 Makes a random generator with a fixed seed. Seed, generator Only the DataLoader's shuffle uses this generator, so the batch order is repeatable.
148 to 149 Builds the DataLoader. shuffle=(split == "train") shuffles train only. batch_size is 64 by default. num_workers=0 loads in the main process. Mini-batch training Shuffling helps learning. Val and test are not shuffled, so the order always matches the file order.

Two details to know. First, the parameter named augment shadows the function augment() inside get_loader. This works, because get_loader only passes the boolean on to make_transform(augment), but it is a naming trap. Second, the random augmentations use PyTorch's global random number generator, not the generator object. So repeatability of the augmentations depends on set_seed from src/utils.py (or on the code calling it), not on the seed argument of get_loader. The seed argument only fixes the subset and the shuffle order.

5. How the split is made, step by step

Command: python -m src.dataset (run once, from the repo folder, with the venv on). It runs check_split(make_split()).

  1. The code opens the EuroSAT RGB data from data/eurosat/2750 with download=False. torchvision finds 27,000 (path, label) pairs and 10 class names.
  2. A table is built with one row per image: path (relative, with /), label (0 to 9) and class_name.
  3. First cut with train_test_split(..., train_size=0.7, stratify=label, random_state=42): about 70% of the rows go to train (18,900) and the other 30% to the rest (8,100).
  4. Second cut with train_test_split(rest, train_size=0.5, stratify=label of rest, random_state=42): the rest is cut in half. Each half gets 4,050 rows: validation and test.
  5. Each row gets its split value (train, val or test).
  6. The table is saved to data/splits.csv, with no index column.
  7. check_split runs and prints: - Leakage check: OK - split sizes: {'train': 18900, 'val': 4050, 'test': 4050} - no file appears in two splits; every class keeps its share in every split
  8. The notebook repeats this check (cell 3) and prints the crosstab of classes by split (section 8).

Because the seed is fixed at 42, running the cut again on the same data gives the same file. This was checked in the work (the split was made twice and the file was the same both times).

6. Why the split must be fixed and how we prove no leakage

Why it must be fixed. Every model in the team must be trained on the same train images and scored on the same test images. Otherwise a higher score could come from an easier test set, not a better model. A fixed split, saved in a file that everybody commits, makes the scores comparable. A random split made fresh on each laptop would give five different test sets. The seed (42) and the saved CSV make the split fixed. The CSV is the real source of truth: the code only reads it after the first run.

Why stratified. The classes have different sizes (2,000 to 3,000). A plain random split could put most of one class into train by chance. Stratifying makes each class keep the same 70/15/15 share in every part. This matters most in the data-efficiency study, where at 5% the smallest class has only 70 train images.

How we prove there is no leakage. The checks are:

  1. Sizes. check_split asserts that the split sizes are exactly 18,900, 4,050 and 4,050. Any other number stops the program.
  2. Unique file names. check_split asserts that every path appears once. A file cannot be in two splits if it appears only once.
  3. Stratification. check_split builds the class-by-split table and checks that every count is within 1 of the exact expected count. In our data the expected counts are whole numbers, so all counts are exact (for example AnnualCrop has 2,100 / 450 / 450, and Pasture has 1,400 / 300 / 300).
  4. Identical content (MD5). Notebook cell 5 reads all 27,000 files, computes an MD5 for each and counts the MD5 values that appear in more than one split. The result is 0, so no byte-identical picture is in two splits, even under a different file name.

What the checks do not prove: they do not find neighbouring tiles. EuroSAT tiles are cut from larger scenes, so two tiles from the same area can be in train and test. They look alike, so a model may score higher than on a truly new area. A random split cannot prevent this. The fix would be a split by geographic area, which needs the location of each tile, and EuroSAT does not give that to us in this file. This is stated as a limitation in the report.

7. Why rotations and flips are safe here, and why the test set is never touched

7.1 Rotations and flips

A satellite image is taken looking straight down. There is no "up", no sky, and no fixed direction for roads or fields. A field rotated 90 degrees is still a field, and a river flipped left-right is still a river. So the class label does not change. This is why these transforms are label-safe for EuroSAT.

They are also exact. The rotations use only 0, 90, 180 and 270 degrees. A rotation by any other angle would need interpolation, which mixes neighbouring pixels and leaves empty corners. Right-angle moves only change where pixels are; no value is created or lost. Notebook cell 20 checks this: the sorted pixel values of the image are identical after 50 random augmentations.

Together the rotations and the two flips give all 8 orientations of a square tile. The model sees more variety without any new images.

Why this would not work for digits. A handwritten "6" rotated 180 degrees looks like a "9", and a flipped "2" or "5" is not the same digit. The label would change, so rotations and flips are not label-safe for digits. For satellite tiles there is no such confusion, because the class depends on the land cover, not on the direction of the picture.

Why only on training images. Augmentation adds variety for learning. Validation and test must stay as they are, so that every model is scored on the same pictures. The code enforces this in two ways: make_transform(use_augment=False) is the default in EuroSATDataset, and get_loader raises an error if someone asks for augmentation on val or test.

7.2 Why the test set is never touched

The test set is the only honest estimate of how the model will do on new images. It must be used once, at the end, for the final score. If we looked at it while making choices (which model, which learning rate, when to stop), the choices would be tuned to it, and the final score would be too optimistic. This is leakage of a different kind: the test set leaks into the decisions.

In our code and notebook this is handled by four rules:

  1. The EDA (colours, histograms, percentiles) uses train images only (cell 14 and cell 17 read train, not the whole df). The class counts (cell 8) and the leakage checks are about the whole table, but they look only at file names and sizes, not at pixel values, and they are needed to prove the split.
  2. Decisions are made on the validation set. Only the training split is shuffled and augmented.
  3. get_loader refuses fraction or augment on val or test, so the val and test sets cannot be changed by a setting.
  4. The test set is used only in the final evaluation, which is in another part of the project.

9. Honest notes and open points

  • The augment name is used for both a function and a parameter of get_loader. It works, but it is confusing.
  • Augmentation randomness is not controlled by the seed argument of get_loader. It depends on the global PyTorch seed (set by set_seed in src/utils.py). A run is repeatable only if that is set as well.
  • The leakage check in check_split compares file names and counts. The byte-level check is in the notebook, not in the code. A teammate who runs only python -m src.dataset does not get the MD5 check.
  • The 1-image tolerance in check_split is more lenient than needed for this data, where every count is exact.
  • The notebook was run on Python 3.13 (metadata in the notebook), while the team standard is Python 3.12. The code should behave the same, but this was not tested on 3.12.
  • Neighbouring-tile leakage is not checked and cannot be removed with a random split. It is a stated limitation.
