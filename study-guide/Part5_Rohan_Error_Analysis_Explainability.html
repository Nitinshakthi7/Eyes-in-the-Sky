Part 5 – Rohan: Error analysis and explainability (Part E)

1. What my part is

Part E asks two questions about our best model: where does it go wrong, and what does it look at when it is right? The model is MobileNetV2, fully fine-tuned, seed 0 (models/mobilenet_v2_full_frac1_seed0.pth), scored on the 4,050 test tiles that were never used for training or for choosing anything. The main files are src/evaluate.py (predictions, confusion matrix, per-class report, list of mistakes), src/gradcam.py (Grad-CAM written by hand) and notebooks/04_evaluation_and_explainability.ipynb, which all three appear in my log. The other Part E scripts are the Grad-CAM runs over all classes, the confidence-drop test, its control, the t-SNE plot, the two error-picture scripts and src/train_part_e.py, the seed-4 scratch CNN runs. The headline result is 3,981 of 4,050 right (98.30% accuracy on the CPU re-scoring, 98.20% macro-F1) and 69 mistakes. The most useful finding is that the mistakes are concentrated in the crop and vegetation classes. The least useful one, which we must say honestly, is that Grad-CAM on this model does not point at anything more important than the rest of the image. The t-SNE plot is a picture of the features, not a measurement.

2. Definitions

Test split. The 4,050 images in data/splits.csv marked test. They are used once to score a finished model and never to make a decision.

Checkpoint (weights file). The saved numbers of a trained model (.pth file). Loading it gives back the trained model without training again.

Prediction. The class the model says an image belongs to. It is the class with the highest score, found with argmax.

Confusion matrix. A 10 x 10 table. Each row is the real class, each column is the predicted class. The diagonal holds the correct answers; every off-diagonal cell counts one kind of mistake.

True positive / false positive / false negative. For one class: a true positive is an image of the class called that class; a false positive is an image of another class called this class; a false negative is an image of this class called another class.

Precision. Of all images the model called class X, the share that really were X. Low precision means X is called too often.

Recall. Of all real images of class X, the share the model found. Low recall means X is missed too often.

F1 score. The harmonic mean of precision and recall, 2 x P x R / (P + R). It is high only when both are high.

Accuracy. Correct predictions divided by all predictions. It is dominated by the bigger classes.

Macro-F1. The F1 of each class, then the plain average of the 10 values. Every class counts the same, whatever its size.

Support. The number of real test images of a class (for example 450 AnnualCrop, 300 Pasture).

Classification report. A table with precision, recall, F1 and support for each class, plus the accuracy and the macro and weighted averages. Saved as results/mobilenet_v2_full_frac1_seed0_classification_report.csv.

Most-confused pair. A pair (actual class, predicted class) with many mistakes, for example 7 AnnualCrop images called PermanentCrop.

Misclassified list. The file results/misclassified_images.csv: one row per wrong test image with its path, the real and the predicted class.

Activation. The numbers a layer produces for one image. A "feature map" is one channel of those numbers, a small grid. For our 64 x 64 tile, the last MobileNetV2 block gives 1,280 maps of 2 x 2.

Gradient. How much the output score would change if one number in a layer were changed a little. A positive gradient means "more of this feature increases the score".

Forward hook. A function PyTorch calls automatically when data passes forward through a layer. Ours copies the activations out.

Backward hook. A function PyTorch calls when gradients pass backward through a layer. Ours copies the gradients out.

Backward pass (backpropagation). Computing the gradient of a score with respect to every weight and activation, starting from the output and going backward through the network. score.backward() does this.

Grad-CAM. Gradient-weighted Class Activation Mapping. It builds a coarse heat map showing which regions of the last convolution layer pushed the chosen class score up.

Global average pooling. Replacing each feature map by its mean. It turns 1,280 maps of 2 x 2 into 1,280 single numbers. Our classifier and our t-SNE features both use it.

ReLU. The function max(0, x). Negative values become 0. In Grad-CAM it keeps only the regions that push the score up.

Heat map. A picture of numbers, here shown with the colour map "jet" (blue for low, red for high).

Overlay. The heat map drawn semi-transparently on top of the original image.

Bilinear interpolation. Smooth resizing of a small grid to a big one by blending neighbouring values. We use it to stretch the 2 x 2 map to 64 x 64.

Saliency. A general name for maps that show which input pixels matter for a prediction. Grad-CAM is one kind of saliency map.

Softmax. A function that turns the 10 raw scores into probabilities that add up to 1.

Confidence. Here, the softmax probability of the class the model chose (or, in the confidence-drop test, of the true class).

Control experiment. A second test run in the same way as the first, but with a different choice, so that we can tell whether the first result means anything. Ours compares the hottest patch with the coldest patch and a random patch.

Confidence drop. How much the confidence falls after part of the image is hidden. A big fall suggests that the hidden part mattered.

Embedding (feature vector). The list of numbers that a network produces for one image before the final classifier. Here, 1,280 numbers per image.

t-SNE. t-distributed Stochastic Neighbour Embedding. It places high-dimensional points in 2 dimensions so that points that were close stay close. It is for looking, not for measuring.

Perplexity. A t-SNE setting that says roughly how many neighbours each point should consider. We use 30.

PCA initialisation. Starting the t-SNE layout from the main directions of the data (principal component analysis) instead of random positions. It makes the result more repeatable.

Random seed. A number that fixes the random choices, so the same run gives the same result. Our seed for the t-SNE sample is 42.

Stratified split and data fraction. A split that keeps each class in the same share. A fraction of 0.05 means 5% of the training images, chosen per class.

Seed-4 runs. Extra scratch CNN training runs with seed 4 at 5%, 10% and 25% of the training images, stored in results/metrics.csv.

Normalisation (ImageNet mean and std). Each colour channel is shifted and scaled with fixed numbers (mean 0.485, 0.456, 0.406; std 0.229, 0.224, 0.225). The value 0 after normalisation is therefore the ImageNet average colour, not the average colour of EuroSAT.

model.eval() and torch.no_grad(). eval() switches off training-only behaviour (dropout, batch-norm updates). no_grad() stops PyTorch from storing gradients when we only need predictions.

Quantile and top-k. quantile gives the value below which a share of the numbers fall. topk gives the positions of the largest values. We use them to pick the hottest and coldest pixels.

3.2 src/gradcam.py: Grad-CAM written by hand

This file is the core of the explainability part. The function takes one image (shape 1 x 3 x H x W), a layer, and returns a heat map (64 x 64, values 0 to 1) and the predicted class.

def grad_cam(model, image, layer):
    """Generate a Grad-CAM heatmap for one image.

    Args:
        model: trained classification model
        image: tensor shaped (1, 3, H, W)
        layer: target convolutional layer

    Returns:
        heatmap: tensor shaped (H, W), values between 0 and 1
        predicted_class: integer predicted class
    """

    model.eval()

    activations = None
    gradients = None

    # Save feature maps from the target layer
    def forward_hook(module, inputs, output):
        nonlocal activations
        activations = output

    # Save gradients flowing through the target layer
    def backward_hook(module, grad_input, grad_output):
        nonlocal gradients
        gradients = grad_output[0]

    forward_handle = layer.register_forward_hook(forward_hook)
    backward_handle = layer.register_full_backward_hook(backward_hook)

4. How Grad-CAM works, step by step

Grad-CAM answers: which places in the last feature map made the chosen class score go up? It needs one forward pass, one backward pass and two hooks.

  1. Forward pass. The tile goes through MobileNetV2. The forward hook on model.features[-1] keeps the activations A^k (1,280 maps of 2 x 2 for our 64 x 64 input, because the network divides the size by 32).
  2. Score. Take the score of the chosen class (the logit, before softmax), y^c.
  3. Backward pass. score.backward() gives the gradient dy^c / dA^k at every position of every map. The backward hook keeps these.
  4. Weights (alpha). For each map k, average the gradient over the positions:

alpha_k^c = (1 / Z) x sum over i and j of (dy^c / dA^k_ij)

where Z = number of positions = 2 x 2 = 4. In the code this is gradients.mean(dim=(2, 3)). A large alpha means: making this map stronger would raise the class score a lot. 5. Weighted sum and ReLU. Combine the maps and keep only positive values:

L^c = ReLU( sum over k of alpha_k^c x A^k )

The ReLU keeps the regions that support the class. Negative regions are dropped. 6. Resize. Bilinear interpolation stretches the 2 x 2 map to 64 x 64. 7. Normalise. Subtract the minimum and divide by the maximum, so the map runs from 0 to 1. 8. Overlay. Draw the map in "jet" colours on the image, semi-transparent.

Why the last convolution layer? It is the deepest layer that still has spatial positions. Deeper layers know more about the class, but after global average pooling the position is gone. Earlier layers have finer grids (for a 64 x 64 input, the earlier blocks have 16 x 16, 8 x 8 and 4 x 4 positions) but respond to simpler things like edges. The last block is the best trade-off for "what" and "where", but on 64 x 64 tiles it only has 2 x 2 positions, which is why our maps are coarse.

What Grad-CAM is not. It is one method, one layer, one image. It does not prove what the model "thinks". Our control (section 6) found the heat maps do not single out a more important area on this model.

  • AnnualCrop called Pasture: dark green, uniform fields with faint boundaries. Several are 64 to 78% sure, one is 100% sure.
  • HerbaceousVegetation called Pasture or PermanentCrop: mixed, patchy vegetation, some bare ground. Confidence ranges from 54% to 99%.

Confidence. The model is 99.0% sure on average when it is right and 76.3% sure when it is wrong (CPU re-scoring, section 9.4). A rule "send to a person when under 80% sure" would catch 39 of 69 mistakes but also flag 60 of 3,981 correct answers. The threshold was looked at on the test set, so it is an illustration, not a tuned rule. The main lesson is that mistakes are not always unsure: 56 of 69 were below 90%, but the model still gives a high probability to its wrong answer in many cases.

6. What the Grad-CAM control showed

The first test (confidence drop). For 50 correctly classified test images we hid the hottest 20% of pixels (set to the ImageNet average colour) and measured the confidence of the true class.

  • Average confidence before: 97.72%. After: 96.64%. Average drop: 1.08 points (0.0108).
  • In 10 of the 50 images the model became more confident after hiding the "hot" area.
  • A second laptop re-run gave 0.61 points on the same 50 images (as recorded in results/part_e_analysis.md; that value is not in the saved CSV).

On its own this looks like "the hot area matters a little". It does not show that, because nothing was compared with it.

The control (gradcam_sanity_check.py). For 200 test images, three patches of 25% of the pixels were hidden in turn: the hottest 25%, the coldest 25%, and a random 32 x 32 square.

Patch hidden Mean confidence drop Prediction changed
Hottest 25% (Grad-CAM) 0.064 14 of 200
Coldest 25% (Grad-CAM) 0.061 14 of 200
Random 32 x 32 square 0.089 17 of 200
  • Hiding the hottest area hurt more for 109 images and less for 91.
  • Hottest minus coldest, paired on the same 200 images: mean difference 0.003, standard error 0.017, p = 0.87 (my own paired t-test on the saved CSV; not in the repo). This is no difference at all.
  • The random square did slightly more damage than the hottest patch (paired p = 0.08, not significant at 5%).
  • The medians are very small (hottest 0.0008, coldest 0.0002, random 0.0014): most patches barely change the confidence. The means are driven by a few images with big drops.

Where the heat is. The hottest quarter of the 2 x 2 map was the bottom-right in 160 of 200 images (80%), the top-right in 36, the bottom-left in 4 and the top-left in none. The same lower-right pattern can be seen in gradcam_all_classes.png: the heat is in the lower-right for many images whatever the content.

What this shows. On this model and at this size, the Grad-CAM heat map does not identify a part of the tile that matters more than the rest. Hiding the hottest area does no more harm than hiding the coldest, so the heat maps are not evidence of what the model uses. It also shows the maps mostly show a position (bottom-right) rather than the content of the image.

What this does NOT prove.

  • It does not prove Grad-CAM is useless in general. It is one method, on one model, one layer, one image size.
  • It does not prove the model ignores the image content. Our guess that the model uses texture spread over the tile is not tested.
  • The patch is a solid colour, which is unnatural and can itself change the model's output in ways unrelated to importance. The first version of the control used scattered random pixels; it was dropped because scattered noise damages an image far more than one solid patch, so that comparison was unfair.
  • The confidence is very close to 1 for most correct images (mean 0.98), so there is little room for a drop. A ceiling effect can hide a real difference.
  • The top-k "hottest" pixels form an irregular blob, while the random patch is a square. The shapes differ, so the comparison is not perfectly fair either.
  • 200 images, one seed, one model.

Ideas not tried (also in the notebook): Grad-CAM on an earlier block with a finer grid, or enlarging the tile before Grad-CAM, and a control with other fill colours.

7. What t-SNE shows and what it does not show

The plot results/figures/mobilenet_v2_tsne.png uses 1,000 random test images, each as the 1,280 numbers after global average pooling, reduced to 2 dimensions with perplexity 30.

What it shows.

  • Ten groups, one per class. Each group is a compact region. The features of unseen test images are organised by class even though t-SNE was never told the labels. It only uses the features; the colours are added afterwards.
  • PermanentCrop (pink) sits in the middle, between HerbaceousVegetation (green, above) and AnnualCrop (blue, below), with a few points at the edge. This is the picture of the 7 + 5 mistakes in the confusion matrix.
  • Pasture (brown) is a separate group next to HerbaceousVegetation and PermanentCrop.
  • Highway (red) and River (yellow) are separate groups, far apart from each other.
  • Residential (grey) and Industrial (purple) are close on the left, with a few grey points at the edge of the purple group. Matches the Industrial -> Residential and Residential -> Industrial mistakes.
  • SeaLake (cyan) is separate, with a small sub-group at the bottom.

What it does not show.

  • It does not show how far apart two groups really are. Distances between groups on a t-SNE plot have no meaning, and neither do the sizes of the groups.
  • It does not show accuracy. Points inside a group can still be wrong, and a mistake can sit in the middle of the right group.
  • It does not show the model's decision boundary. The 10-class layer that decides is not in the plot.
  • The picture depends on the settings. Another perplexity or seed would give a different layout. We used one seed (42) and one perplexity (30).
  • Our sample is 1,000 images, not the 2,000 in the plan. The plan's number was not used in the code, the notebook or the report (see section 8).
  • The model was trained on these classes, so clean groups are expected. The useful point is that unseen test images still group well.
